# Bulk posting guide

How to use `POST /api/generate/bulk` to append many dataset entries in one
request instead of clicking Send in the browser, or making one HTTP call per
entry. This is a companion to the shorter reference in the main
[README](../README.md#http-api-for-scripting) — this doc walks through
actual usage end to end.

---

## Before you start

Two things need to be running first:

1. **`app.py` must be running.** From the project folder:

   ```bash
   python3 app.py
   ```

   By default it listens on `http://127.0.0.1:8942/`. If that port is taken,
   it automatically tries the next few ports and prints which one it landed
   on — check the terminal output if you're not sure which port to hit.

2. **Ollama must be running, if you're using the Ollama backend.** The bulk
   endpoint calls out to Ollama the same way the UI does — it does not start
   Ollama for you. Either:

   ```bash
   ollama serve
   ```

   in a separate terminal, or start it from the running app itself via
   `POST /api/ollama/start` (this is what the UI's "Start Ollama" button
   calls):

   ```bash
   curl -s -X POST http://127.0.0.1:8942/api/ollama/start
   ```

   You can check status at any time with:

   ```bash
   curl -s http://127.0.0.1:8942/api/ollama/status
   # {"running": true}
   ```

   If you're using the Kobold.cpp or OpenAI-compatible backend instead, this
   step doesn't apply — but that backend needs to be reachable at the URL
   you configure (Kobold.cpp's default `http://localhost:5001`, or whatever
   `openai_base_url` you pass for an OpenAI-compatible endpoint).

Everything below assumes the server is up at `http://127.0.0.1:8942/`.

## The basic shape

```bash
curl -s http://127.0.0.1:8942/api/generate/bulk \
  -H "Content-Type: application/json" \
  -d '{
    "filename": "/path/to/dataset.jsonl",
    "model": "qwen35:latest",
    "backend": "ollama",
    "max_tokens": 300,
    "entries": [
      "Write a haiku about rain.",
      "Write a haiku about the ocean.",
      "Write a haiku about mountains."
    ]
  }'
```

- `filename` — required. `.json` writes/rewrites a JSON array; `.jsonl`
  appends one JSON object per line. Either extension works the same way it
  does from the UI, and the file is created if it doesn't exist yet.
- `entries` — required, non-empty list. Each item becomes one prompt sent to
  the model, and the result is appended as one ChatML entry.
- Everything else (`model`, `backend`, `max_tokens`, `system`, `temperature`,
  `top_p`, `seed`, `openai_base_url`, `openai_api_key`, `openai_model`) is a
  **default applied to every entry** unless that entry overrides it (see
  below).

The whole batch is generated sequentially, then written to disk in a single
write — not one write per entry — so this is meaningfully faster than
looping `POST /api/generate` yourself for large batches, on top of being
fewer HTTP round-trips.

## Importing pre-written pairs (no model call)

If you already have the response text — imported from somewhere else, hand-
written, whatever — give the entry a `"response"` key. That entry is
appended exactly as given and the backend is never called for it:

```bash
curl -s http://127.0.0.1:8942/api/generate/bulk \
  -H "Content-Type: application/json" \
  -d '{
    "filename": "/path/to/dataset.jsonl",
    "entries": [
      {"prompt": "What is 2+2?", "response": "4"},
      {"prompt": "Capital of France?", "response": "Paris"}
    ]
  }'
```

This mode needs `app.py` running but has **no dependency on Ollama/Kobold
at all** — it's a plain "append this JSON to that file" operation. Useful
for merging in data generated by some other pipeline while still going
through the app's duplicate-checking and JSON/JSONL handling.

You can freely mix plain-string entries (generated) and object entries with
`"response"` (imported) in the same batch — see the [README example](../README.md#bulk--post-apigeneratebulk).

## Per-entry overrides

Any object entry can override the batch-level defaults just for itself.
Useful for comparing models/backends within one dataset, or varying sampling
per entry:

```bash
curl -s http://127.0.0.1:8942/api/generate/bulk \
  -H "Content-Type: application/json" \
  -d '{
    "filename": "/path/to/dataset.json",
    "model": "qwen35:latest",
    "backend": "ollama",
    "max_tokens": 300,
    "entries": [
      "Describe a sunrise.",
      {"prompt": "Describe a sunrise.", "model": "eve:latest"},
      {"prompt": "Describe a sunrise, tersely.", "temperature": 0.2, "max_tokens": 60}
    ]
  }'
```

The first entry uses the request-level defaults (`qwen35:latest`, 300
tokens). The second swaps the model. The third lowers temperature and the
token budget. All three still land in the same dataset file.

A system prompt or prior-conversation context can also be set per entry:

```json
{"prompt": "And then what happened?",
 "system": "You are narrating a bedtime story.",
 "context": [
   {"role": "user", "content": "Once upon a time..."},
   {"role": "assistant", "content": "...there was a small dragon who loved rain."}
 ]}
```

## Duplicate handling

By default, `allow_duplicate` is `false` for the bulk endpoint — same
behaviour as the UI. The dataset file is loaded once at the start of the
request, and every prompt (both already in the file, and already appended
earlier *in this same batch*) is tracked, so within-batch duplicates are
caught too:

```bash
curl -s http://127.0.0.1:8942/api/generate/bulk \
  -H "Content-Type: application/json" \
  -d '{
    "filename": "/path/to/dataset.json",
    "model": "qwen35:latest",
    "entries": ["Say hi.", "Say hi."]
  }'
```

The second `"Say hi."` comes back as `{"ok": false, "duplicate": true,
"error": "duplicate prompt"}` in `results`, and is not appended — but the
first one still is, and the request as a whole still returns `200`. Set
`"allow_duplicate": true` at the top level to disable this check for the
whole batch.

---

## Handling failures mid-batch

By default (`stop_on_error: false`), a failed entry — empty prompt, backend
error, missing required field for the chosen backend — is recorded in
`results` and skipped, and the rest of the batch still runs:

```json
{
  "ok": true,
  "appended": 8,
  "failed": 2,
  "skipped_duplicates": 1,
  "total_entries": 8,
  "results": [ /* one result per input entry, same order */ ]
}
```

Set `"stop_on_error": true` if you'd rather the whole batch halt at the
first failure — nothing after the failing entry gets processed or written,
though anything appended *before* it is still saved:

```bash
curl -s http://127.0.0.1:8942/api/generate/bulk \
  -H "Content-Type: application/json" \
  -d '{
    "filename": "/path/to/dataset.json",
    "model": "qwen35:latest",
    "stop_on_error": true,
    "entries": ["First.", "", "Never reached."]
  }'
```

Here `"First."` gets appended, the empty prompt fails and stops the batch,
and `"Never reached."` never runs.

Every result in the `results` array is one of:

```json
{"ok": true, "entry": {"messages": [...]}}
{"ok": false, "error": "prompt is required"}
{"ok": false, "duplicate": true, "error": "duplicate prompt"}
{"ok": false, "error": "backend request failed: ..."}
```

## Reading the response

```json
{
  "ok": true,
  "results": [ /* per-entry, same order as input */ ],
  "appended": 3,
  "skipped_duplicates": 1,
  "failed": 0,
  "total_entries": 47
}
```

`total_entries` is the dataset file's total entry count *after* the batch —
handy for confirming a big scripted run actually landed everything you
expected, or for driving a "keep generating until N entries exist" loop
from your own script.

## A small Python example

```python
import requests

BASE_URL = "http://127.0.0.1:8942"

# Optional: make sure Ollama is up before a big Ollama-backed batch.
status = requests.get(f"{BASE_URL}/api/ollama/status", timeout=5).json()
if not status["running"]:
    requests.post(f"{BASE_URL}/api/ollama/start", timeout=30)

topics = ["volcanoes", "coral reefs", "the northern lights", "deserts"]

resp = requests.post(
    f"{BASE_URL}/api/generate/bulk",
    json={
        "filename": "/home/kim/datasets/nature_facts.jsonl",
        "model": "qwen35:latest",
        "backend": "ollama",
        "max_tokens": 250,
        "entries": [f"Give one interesting fact about {t}." for t in topics],
    },
    timeout=600,  # a big batch can take a while — this is a synchronous call
)
resp.raise_for_status()
result = resp.json()
print(f"appended {result['appended']}, failed {result['failed']}, "
      f"total now {result['total_entries']}")
```

Note the generous `timeout` — the whole batch runs synchronously inside one
HTTP request, so for a large `entries` list (or a slow model) the request
can legitimately take a long time to return. There's no streaming/progress
reporting on this endpoint; if you want visible progress for a large run,
either call `POST /api/generate` in a loop from your own script (checking
`/api/dataset_info` between calls if you want a live count) or split a big
batch into a few smaller bulk calls.
